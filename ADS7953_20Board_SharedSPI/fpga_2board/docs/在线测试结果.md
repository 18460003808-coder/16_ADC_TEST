# ADS7953两板工程在线测试结果

测试日期：2026-09-09

## 测试连接

- FPGA：EP4CE40F23C8
- 下载器：USB-Blaster [USB-0]
- 串口：COM9，CH340，115200-8-N-1
- SignalTap：50 MHz采样，64K深度
- 测试命令：连续发送ASCII `T`（`0x54`）

## 实测结果

- FPGA配置成功，JTAG器件ID为 `0x020F40DD`。
- 最终30秒密集测试发送27,700次 `T`，串口收到0字节。
- SignalTap得到65,537个有效采样点。
- 板0片选持续产生SPI帧；捕获到约81个帧窗口。
- 完整片选窗口宽800个采样点，即16 us；每个窗口有16个SCLK上升沿，SCLK约1 MHz。
- 相邻帧CS高电平约6个采样点，即120 ns。
- 板1片选始终为高，没有进入板1采集。
- `adc_sdo`在整个采样窗口始终为高，相当于每帧收到 `0xFFFF`。
- `uart_rxd`在最终波形中有10次跳变，证明CH340发送信号已经到达FPGA输入端。
- `uart_txd`始终为高，FPGA没有发送结果帧。
- 停止发送串口命令后又执行了一次64K空闲抓取：约1.31 ms内，`CS0=CS1=1`、`SCLK=0`、`SDI=0`，但`adc_sdo`仍始终为高。

## 结论

FPGA内部的片选和SCLK时序正常，但FPGA在`PIN_H17`上没有读到有效SDO。读取模块要求先收到通道0，再按0至15顺序完成一轮；当前持续收到 `0xFFFF`，因此一直等待通道0，不能结束板0，也不会进入板1或发送串口结果。

这不是上位机堵塞，也不是ADS7953配置字或采样边沿问题。`0x93C0`用于把Auto-2末通道设为CH15，`0x3C40`用于进入Auto-2、复位到CH0并选择Range 2，配置含义正确。[来源: ads7953.pdf, 8.4.6 Operating in Auto-2 Mode, pp.38-41, Table 5/Table 6]

空闲抓取是更直接的定位证据：级联板原理图在公共SDO端设置了10 kΩ下拉；ADS7953在CS拉高后应将SDO切换为三态，3 V数字接口下最大延迟为21 ns。[来源: SCH_Schematic1_2026-09-07.pdf, p.1, R32] [来源: ads7953.pdf, 7.9 Timing Requirements, p.17, td4] 现在全部CS已连续拉高约1.31 ms，`PIN_H17`却仍为高。因此，在“板卡和插接方向确认正确”的前提下，优先级最高的是核实级联板U1-19到FPGA `PIN_H17`的对应关系，以及R32是否实际装配并连接到公共SDO；SPI状态机不是当前故障点。

## 必查引脚

两板工程当前使用：

| 信号 | FPGA引脚 |
|---|---|
| CS0 | B21 |
| CS1 | C20 |
| SCLK | J17 |
| SDI | H21 |
| SDO | H17 |

原 `ADS7953_0-5V` 单板工程使用的是CS=K19、SCLK=M19、SDI=K21、SDO=K22。两板工程改用J11接口，当前文档把J11-19映射为H17；本地FPGA用户手册仅说明J11是Bank 6扩展口，没有提供J11逐针到FPGA焊球的完整表格，因此尚不能只凭本地文档确认H17映射。[来源: EP4CE30VER6.1D硬件用户手册.pdf, FPGA核心板资源/扩展I/O, pp.6-9]

最新空闲在线波形已导出到 `output_files/online_test.csv`，也保存在 `stp2.stp` 的 `online_test` 数据日志中。前一次连续命令抓取的统计结果保留在本报告“实测结果”中。

Quartus 13.1命令行采集实际使用了立即触发。用GUI观察时，请在Setup页确认 `uart_rxd` 的触发单元格显示Low（或Falling Edge）；若仍显示Don't Care，右键该单元格重新选择一次并保存即可，该运行时触发修改不需要重新编译SOF。
